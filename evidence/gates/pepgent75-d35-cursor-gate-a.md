## 二、对 §五 `A-1`–`A-3` 的逐项回答

### A-1：第 1 处：T 早于第一项提交时钳到第一项，是否属于 D35-01 v3 公式在轴外输入上的私有补全，不触及产品意图或公开契约（C1–C3）？
- **答复：** **是，确认属于 `D35-01 v3` 公式在轴外（左 padding，`T < 0`）输入上的单仓私有补全（K3/K2），不触及产品原始意图与公开契约，无需立案。**
  - 运行时间轴以 `run.startedAt`（即 `seq = 1` 的 `at`）为原点 `0`；仅当指针落入左侧 12px padding 区域时 `T < 0`。`replay-at.ts` 将 `T < first.minute` 钳到 `first.minute` 返回第一项有效提交状态，不改变 wire、ADT、`packages/ui` 属性或 `live` 判据，完全符合 `D10-08` 单仓私有算法范畴。

### A-2：第 2 处：按 F2–F5 和 `(U)` U2（全流程不收缩），同刻提交（含非派生运行 `at=1` 的空图）与间隔小于 1px 的提交拖不到，是否构成 F10 S2“任意历史序号 k 经拖动指定”的缺口，需要修订 D35-01 v3（C4–C7）？
- **答复：** **不构成缺口，不需要修订 `D35-01 v3`，也不需要立 P0 议案（维持 `PR#75` 已合入的 `replay-at.ts` 实现）。** 具体依据如下：
  1. **非派生运行的 `seq = 1`（`run_started`）在契约上本来就不是独立的“已提交状态”（属 K1）：**
     - 按 `SDES/store.md:94`（`(D)`），非派生运行没有独立的“创建运行”请求，而是在第一次正式步提交（`POST /runs/steps` 带 `open: { session }`）的**同一事务**里创建运行、写入 `run_started`（`seq = 1`）并写入第一条 `step_committed`（`seq = 2`）；只有派生运行（`POST /runs/derive`）才在独立于步提交的物化事务里写入携带继承节点的 `run_started`（`seq = 1`）。
     - 按 `SDES/store.md:137`（`(D)`）明文定义：“**一次提交的记录在其提交级事件（`step_committed`，或派生运行 `seq = 1` 的 `run_started`）的序号处整体生效**”。
     - `D35-01 v3` 在 `how` 列写明“收录本运行每条 `run_started`（`seq = 1`，**派生运行的物化锚点在此生效，见 `SDES/store.md:94,137`**）与 `step_committed` 事件”，并采用 `k = max{ seq ∈ commits | at(seq) ≤ T }`，其设计用意正是：
       - 对**派生运行**，`POST /runs/derive`（`seq = 1`）与后续 `POST /runs/steps`（`step_committed`）是两次不同时刻的提交，`at(1) < at(首次 step_committed)`，游标拖到 `at(1)` 时 `max` 精确落到 `seq = 1`（派生物化锚点）；
       - 对**非派生运行**，`seq = 1`（`run_started`）与 `seq = 2`（首次 `step_committed`）属于同一次 `POST /runs/steps` 事务（`at(1) = at(2)`），`max` 自动落到该次提交真正的提交级事件 `seq = 2`，而不会落到现实中从未独立存在过的空图 `seq = 1`。
     - 因此，非派生运行同刻 `(seq=1, seq=2)` 取 `seq = 2` 恰恰是 `SDES/store.md:94,137` 与 `D35-01 v3` 公式的预期结果，绝非契约缺口。
  2. **间隔小于 1px 的提交属于主路径外的极端时间分辨率边缘情况（属 K2）：**
     - `D35-01 v3` 取舍列写明“**F10 S2 在主路径上可达**，游标能落到每一次已提交的状态（含只有根值的提交）”——这是针对 v2 仅按调用节点 `endedAt` 定位从而遗漏“只有根值的步提交”和“派生运行物化锚点”而作的修正，使每次提交事务在 `commits` 中都有时间轴锚点。
     - 按 `SOR/.claude/rules/design-assumes-it-works.md`（“设计阶段只写主路径：禁止考虑边缘情况和竞态处理。边缘情况：不为异常输入、失败分支、超时、重试、恢复、空值或极端规模设计任何处理”），当运行跨度极长且两次步提交间隔在亚像素（`< 1px`）以内时的像素分辨率限制属于典型的极端规模/边缘情况（K2），且 `D35-01 v3` 已保留工具栏“回看到这一步”作为辅助入口，禁止为此改动已通过的连续时间轴公式或增加额外 UI 交互。

### A-3：第 2 处如果判为不构成缺口，F2 中“每一次已提交的状态”的表述是否需要随之修订，以免已通过的正文自相矛盾？
- **答复：** **不需要修订，已通过的 `D35-01 v3` 正文完全自洽。**
  - `D35-01 v3` 的 `how` 列已显式指向 `SDES/store.md:94,137`（“`run_started`（`seq = 1`，派生运行的物化锚点在此生效，见 `SDES/store.md:94,137`）与 `step_committed`”），而 `SDES/store.md:137` 已将每次提交生效的状态定义为“提交级事件（`step_committed`，或派生运行 `seq = 1` 的 `run_started`）”，且取舍列首句已限定在“主路径”上可达。两处合并阅读含义唯一、无自相矛盾，直接由协调席在 `PR#75` 评论中记录两道闸门“不越界、无需修订”的澄清结论即可。
