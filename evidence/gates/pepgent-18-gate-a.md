2. **A4-2：快照方案当然涉及新持久化契约；不加字段的方案也未获自动授权。** `[INFERENCE]` 学生提交画布 A，awaiting 期间改成 B，owner 批准：a 投递 B，b 使修改不能发生，c 投递 A；三者产品行为不同。现行 pending 形状能排除“字段已经存有快照”的说法，却不能从缺字段推出用户已经选了 a 或 b。
3. **A4-3：绑定后修改范围仍是公开生命周期问题。** 现行“来源草稿”指向可变对象还是绑定时内容未定；不能把 store 的正式运行记录不可变，自动扩大成 Lab 所有业务草稿不可变，也不能以草稿可变为理由改写已提交运行事实。该关系应与 discard 放在同一议案里按行明确，不在本席直接选只读或可改。
4. **A4-4：计数与并发分开。** 以 savedVersion 表示服务端保存修订号、保持既有请求/结果形状，可由工程师实现；现行字段没有提供客户端条件更新协议。不得从名称推导新乐观锁、历史版本库或 start 快照，也不把具体增量算法伪称用户意图。本项 P0 针对生命周期，不为普通计数重复立案。
5. **未定范围不吞掉已定行为。** 无 pending 且未绑定草稿的完整 canvas 保存、既有权限与结果、通知模块等不依赖本项选择的实现可继续；“可继续实现”不等于已经把缺失状态行为作为完整功能交付，也不是以 `notSupported` 占位宣称完成。
