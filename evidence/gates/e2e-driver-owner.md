## 二、初分类与分析

**初分：K1（既有决策已覆盖，只需澄清）。不需要新增或修改任何决策正文。**

1. **编写者已由决策点名。** 两个驱动都是 `Pepgent/soroi` 的 `e2e/**` 测试代码。D10-05 明文写“E2E-* spec/runbook……其余 W-08 写”，where 栏点名了 #250、#259（F5）；D10 派工节写“被测实现合入后由 W-08 写 soroi `e2e/**`”（F7）；D16-09 规定 `e2e/**` 只由 W-08 写（F8）；D16-10 规定 W-08 按逐 spec 时点编写（F9）。阶段 C 执行席“另行派工，不在本表范围内”（F10），已通过的决策没有给它 `e2e/**` 写权。
2. **驱动必须在阶段 C 之前合入。** D10-06 把“E2E-* 的测试代码已合入 main”定为阶段 C 的入口条件，阶段 C 的测试者只负责执行与归档（F6）。如果让阶段 C 执行席来写驱动，阶段 C 的入口就无法满足，还要另给它 `e2e/**` 写权，这与 D16-09“一个文件一个 owner”冲突。
3. **issue 正文里的“独立测试者”指执行者。** F1、F2 出自 D8 时期，当时测试者既写又跑。D16-06② 追加的段落已经按 D16-09/10/13 把两件事分开：“owner 为本项统一阶段测试执行者；编写归 D16-09/10 指定路径域”（F4）。“独立”的要求是“不由代码作者的 oracle 自证替代”（F1）：W-08 不是 store、plugin、mux 的产品代码作者；阶段 C 由另行派工的执行席实际运行并判定，这一要求不变。
4. **对 ALL_DONE 与退役的直接后果（只陈述规则，不做排期）：**
   - 两项驱动属于 W-08 在阶段 B 尚未完成的编写工作。按 D16-10，驱动所测代码一旦合入，即可编写（F9）；F15 显示所列被测代码依赖都已关闭。因此 W-08 现在不满足 ALL_DONE 条件，应按 D16-10 核对被测代码已在 `main` 后开工。
   - F07 两个负例场景要等 owner 发布 workload（F16）。这部分在 #221 已有具名 blocker；#259 的全部驱动与 #250 的其余部分可以先写。
   - W-08 何时退役、W-07 何时补位承接 soroi#329，属于协调席在 D16-10“不超过 4 席、释放名额即补入”规则下的排期，不是本项的裁决内容。D16-10 也允许已退役席位以原会话名重新进场编写（F9）。
