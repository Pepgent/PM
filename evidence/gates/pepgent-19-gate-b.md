## 二、对材料 B 问题（`B1-1` 至 `B7-1`）的逐项答复

1. **B1-1（`1a`、`1b` 免票边界）：** `1b` 已在 `D7-06` 与 `LAB-06` 落实；若闸门 A（`A1-1`）确认 `1a` 是 `D7-10`/`D12-09` 的既有直接含义且不改公开契约，W-09 在 `server/lab/**` 本域实现不越过路径白名单或阶段门禁，不需要投票。
2. **B1-2（`1c` 表决期过渡）：** `1c` 属公开 ADT variant 语义缺口，须入 P0。表决期间 W-09 对 `focused_project` 规则暂不触发（规则可建可读，`lab` 与 `project{p}` 照常实现），只暂停依赖 `1c` 的分支，符合 `D10-08`“只暂停依赖部分”。
3. **B2-1（`2c` 失败/恢复/竞态）：** 停机错过的定时点与重启触发间竞态属于 `.claude/rules/design-assumes-it-works.md` 排除的主路径外恢复与竞态处理；由 W-09 在 `server/lab/**` 自定并在 PR 写明，不需要投票。
4. **B2-2（`2a` 表决期过渡与 `2d` 合表）：** `2a` 涉及 `lab.sqlite` 持久化表清单与生命周期，须入 P0；表决期间 W-09 暂不实现事件触发与定时触发、其余已定部分照常推进，符合“只暂停依赖部分”。若闸门 A（`A2-2`）认定 `2d` 触及公开语义或部署前提，应与 `2a` 一并合入本次 P0 议案表决，避免定时触发再等一轮。
5. **B3-1（`3a` 表决期过渡）：** `3a` 触及会话写权限与审批口径，须入 P0；由于 `ConversationRow.owner` 必填，表决期间 W-09 暂不开 Automation 会话、规则与运行记录照常实现，符合“只暂停依赖部分”。
6. **B4-1（`4a` 与第三项合表）：** `4a` 决定 transcript 不可变来源身份与开代路径，与第三项 `3a` 的会话 `owner` 直接牵连；若闸门 A（`A4-1`）确认需表决，应与第三项合入同一张 LAB-09 P0 议案相邻行逐行表决。
7. **B5-1（`5b` 失败判定）：** `5a`（`running → ok` 结束锚点与 `endedAt`）属状态权威与生命周期缺口，须入 P0；在 `5a` 定下主路径锚点且不新增公开 ADT 变体的前提下，`5b`（`running → failed` 的失败分支判定）属主路径外失败处理，由 W-09 自定并在 PR 写明，不需要投票。
8. **B6-1（`6a` 表决期过渡）：** `6a` 涉及持久化外键生命周期或公开错误返回语义，须入 P0（`6b` 竞态由工程师自定）。由于 `6a` 的备选含软删除改表（处置 c）与拒绝有运行删除（处置 a），表决期间 W-09 整条暂停 `automation.rule.delete`（或仅暂停有运行/会话关联分支，待同一张 P0 议案定案后直接实现）而不阻塞规则创建/更新/读取，均符合“只暂停依赖部分”。
9. **B7-1（`7a`、`7b`、`7c` 放行与表决边界）：** 代码改动均在 W-09 `server/lab/**` 白名单内。若闸门 A（`A7-1..A7-3`）确认 `7a`、`7b`（读法一，工具输入不变）、`7c` 是 `D7-10`/`F30 S2`/`F31 ⑥` 的直接澄清，B 侧确认不需要投票、免票放行；若闸门 A 认定 `7b` 为读法二（改 `D7-05` host tool 公开语义/参数）或 `7a`/`7c` 属缺失设计，则将该子项一并合入本次 LAB-09 P0 议案表决。
