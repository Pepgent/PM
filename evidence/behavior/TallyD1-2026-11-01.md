D1 已交付后，TallyD1 收到关于“尽可能使用 low/free”的新指令。它读取了共享 `LEDGER.md`，初始化了一个“记录低成本 agent 使用要求”的 Todo，并给 Main/LedgerU21 发消息（原任务行 306–322）。这部分不是 D1 计票委托的一部分，属于新的台账/治理工作。

- **责任判断：** 更像是新指令到达后未立即由父 agent 分流，而不是 D1 交付本身失败。

### 2.3 关键违规：在共享 `pepgent-soroi` main checkout 调用 Todo DONE，触发全工作区自动提交

这是本对象最重要的过程问题。

证据链如下：

1. 在收到 U25 后，TallyD1 在共享环境中调用 Todo INIT，任务名为“记录低成本 agent 使用要求”，并加入“确认台账编辑归属”等步骤（原任务行 306–310）。
2. 它随后调用 Todo DONE 完成“确认台账编辑归属”（原任务行 322）。
3. 之后它自己披露：Todo 在标记协调步骤完成时**自动生成了提交 `b3f3340`**，返回信息标注为 **“all changes”**；它没有另行执行 `git commit`，也没有继续操作（原任务行 333–340）。
4. 本次自动提交位于共享的 `pepgent-soroi` main checkout，并把其他 agent 正在修改的 `design/*.md` 变更和本次无关的协调信息一起提交。这一影响是本次分析任务指定的事实；transcript 本身直接证明了触发 Todo DONE、自动提交、`all changes` 和 TallyD1 的自我披露。

这不是“手动恶意提交别人改动”：transcript 明确说它没有另行执行 `git commit`。但它仍然是一个**可归责的操作边界错误**：在有其他 agent 并行写入的共享 checkout 中，调用具有自动提交副作用且提交范围为全工作区的 Todo DONE，没有先确保工作区中只有自己拥有的变更，也没有把这项协调工作放到隔离 worktree。结果就是把别人的 `design/*.md` 变更带入了与 U25 协调无关的 commit `b3f3340`。

从返回值 `all changes` 可确定 Todo 的提交边界不是“当前 Todo 所属文件”或“当前 agent 的文件”，而是工作区级别。至于 Todo 内部具体执行 `git add` 的实现细节，transcript 没有展示，不能再做更细的断言。

### 2.4 处置与披露

TallyD1 没有隐藏这个副作用，主动向 Main 说明了 `b3f3340` 的生成，并向 LedgerU25 说明自己没有编辑台账、没有未交付台账改动（原任务行 333–357）。这是良好的披露行为，但不能抵消共享 checkout 的错误提交；正确做法应当是在触发自动提交前阻止该动作，而不是事后报告。

### 主要低效/风险点

- 初期读取了不存在的 `AGENTS.md` 和规则路径，随后才继续查找；这是一次小的路径探查成本，没有证据表明它导致长时间卡住。

- 最大问题不是耗时，而是副作用：在共享 checkout 中使用 Todo DONE。它没有在这个动作前做“我是否拥有所有工作区变更”的检查，也没有使用隔离 worktree；`all changes` 使一次低成本的协调记录变成跨 agent 的聚合提交。
- transcript 中没有看到在 Todo DONE 前后对 `pepgent-soroi` 工作区按文件归属做核对，也没有看到发现 `design/*.md` 后主动停止。即使工具自动提交是已知行为，这个缺少前置边界检查仍是可避免的。

## 4. 对领导层的派活建议

以下建议只针对派活和监督方式，不改变 D1 产品/设计范围：

1. **把仓库和可写路径写进派活契约。** D1 计票 agent 只能在 `Pepgent/PM` evidence 目标路径工作；明确写出“不得进入或修改 `pepgent-soroi`，不得触碰 `design/*.md`，不得为台账/U25 开新工作”。提交前只允许列出的 evidence 文件。
2. **把“共享 checkout 禁止自动提交”写成硬规则。** 任务中明确禁止在共享 main checkout 调用带有自动 commit 的 Todo INIT/DONE 或类似状态工具。Todo 只用于隔离 worktree；共享 checkout 的状态通过 IRC/agent 消息报告即可。
3. **所有可能写文件或改变 Git 状态的 agent 默认使用隔离 worktree。** 如果任务必须在共享 checkout 观察其他 agent 的输出，则该 agent 应被派为只读/协调角色，禁止任何会触发 auto-commit 的工具调用。不要把“秘书任务”默认当成不会改工作区的任务，因为 Todo 本身有副作用。
4. **提交范围纳入验收。** 派活时要求 agent 在提交前确认 staged 文件清单完全落在 allowlist；一旦工具输出 `all changes`、自动提交或出现工作区外路径，立即停止并向父 agent 报告，不得继续把它当作正常完成。这个检查应在任务说明中先给出，而不是等事故后询问。
5. **D1 收口后立即回收角色。** 父 agent 应在 issue/证据/Project 收口后明确发送“任务终止，不接收后续治理指令”；U25、台账和 low/free 使用要求另派给 Governance/台账维护者。这样可以避免已完成秘书实例在新指令到达时再次进入共享 checkout。
6. **若确实必须让它留在共享环境，增加低成本 watchdog。** 可由 `LowTierScope` 监视 Todo DONE、自动提交提示和跨路径写入；一旦出现 `all changes` 或提交路径不在 D1 allowlist，先阻断/通知父 agent。隔离 worktree 优先，watchdog 只是补充而不是替代隔离。
