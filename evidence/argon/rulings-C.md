### C-4：并发、批次与 Subagent 嵌套边界——清除 `fork / 分身`（U24），还原一步内平铺并发与单层远程限制

- **状态：`【定】`**
- **问题拆分与裁决：**
  - **【意图面裁决（Argon · 定）】**
    1. **清除 `fork / 分身` 与 `fork_task` 批次机制（依 U24）：** `soroi` 是独立的 `omp` 定制，不基于 `omomp`，在 `soroi` 中**根本不存在 `fork` / `分身`**。此前历史会话中 assistant 借用 `omomp` 的 `fork_task` 写进 `design/eval.md:5,161-162,166,175` 与 `design/store.md:15` 的“`fork` 出几个分身、各写一步、同一批并发、附一句说明批次目的的话交给别的分身汇总”，以及 `pepgent-omp-soroi-eval/src/batch.ts` 对 `task`/`fork_task` 的拦截，全部属于混淆 `omomp` 与 `soroi` 的错误产物，予以**彻底剔除**。
    2. **`soroi` 中的并发表达（依 U 原文 `#4da22ab4`、`#ea638181`、`#b7357c72`、`#13abc2a1`）：** 在 `soroi` 中，并发是在一步 `eval` 内**平铺书写多条无数据依赖的调用语句**（禁止 `loop`/`map`/`object`/`array`，禁止传递注释），每一路调用的结果各起一个不重名、有语义的 atom 变量名（如 `svm_score`、`rf_score`）；求值引擎自然并发执行这些调用（包括并发运行多个 `Program` 节点或多个 `Agent` subagent），整步正式运行完成后一次提交进 `store`，所有产出的 atom 连同来源调用签名（`svm_score ← run_svm(p1, p2)`）一起出现在未消费提醒中，由中心主 agent 在下一步 `eval` 中直接汇总或比较。
    3. **`eval` 与远程 `Agent` 的嵌套边界（依 U 原文 `#5a37a640`、`#3dbd0473`）：** `eval` 永远只在中心主机的主 agent 上运行，**禁止递归嵌套**（节点函数体内不运行 `eval`）；远程 `Agent` 在自己的运行环境里爱怎么执行怎么执行，但**不允许再接着开远程 `Agent`**（单层远程限制）。先前 `omp-soroi-subagent` 实现者在 `ask` 超时（`01a18f4a #57bc79eb`）后自行决定一刀切禁止所有本地 subagent 嵌套，无 `(U)` 依据。
  - **【技术面（交 leader 技术取舍）】**
    - 移除 `pepgent-omp-soroi-eval/src/batch.ts` 及 `store.ts` 中与 `task`/`fork_task` 相关的 `batches` 表/列，并在 `omp-soroi-subagent` 中只拦截远程 subagent 再开远程 subagent，归技术/实现项交由 leader 安排。

### 2. 半截设计的硬约束与暂定项（E-1..E-5、S-1..S-3、I-1..I-3）

- **E-1（单次调用 `env` 覆盖语法）：**
  - **`【定】`** `eval` 里调用必须保持简单（容器/pod 模板提前构建），禁止魔法值字面量直接做参数、禁止定义 object/array（`(U)` `01a18e3a #c5030836`、`01a18ed5 #13abc2a1, #276d1776`）。
  - **`【暂定】`** 单次调用覆盖默认 `env` 模板的具体语法形式（归技术项投票）。
- **E-2（两阶段 `dry run` / `正式运行` 调用签名与 `pins` 粒度）：**
  - **`【定】`** `dry run` 支持在 Slurm 试跑算法、解决依赖注入与 agent 模拟，从头到尾绝不写 store；正式运行无测试模拟/替身（业务固定值直接写根 atom），不搞“锁定上一次的 eval”，不让弱模型在测试后重新合并写代码（`(U)` `01a18e8a #433e07ba, #48078e3a, #68d36f55, #18d55f0a, #a7f465d2, #8854f464, #32b6f7fd`；`01a18e1f #7ffcea0c`）。
  - **`【暂定】`** `soroi_eval` 工具的 `pins` 具体参数结构（归技术项投票）。
- **E-3（`Pure<T>`、`Capture`、`Fn` 类型闭合与检查）：**
  - **`【定】`** 表层不显式写 `pure`，底层套 `Pure<T>` 类型并支持一值多处分支消费；捕获作为 HKT 能确定性区分 `Program` 体与 `Agent` 体，追踪不必在 Effect 内；atom 不允许嵌套 object/array，TS 多输出必须返回对象；`eval` 只在中心主机运行，禁止递归嵌套（`(U)` `01a18e8a #cab573e1`、`01a18dd4 #01b74874, #946fc403, #cb9f395b`、`01a18ed5 #440c8605, #98d47f20`、`01a18e1f #5a37a640`）。

- **E-4（预定义函数库 / 节点库的持久化、导入与元数据）：**
