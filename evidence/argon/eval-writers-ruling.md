# Argon 专项裁决：谁能写 `eval` 步（主 agent vs `soroi_task` 派出的中心 worker）

> **裁决依据：** 依 `LEDGER.md` U20（D1-16、D1-17）、U23、U24，针对 `evidence/argon/flow-catalog.md` 等处“只有中心主机上的主 agent 运行 eval”与已投票的 `D2-02/03/05`、`D5-06/07/12/13/14/19`（主 agent 经 `soroi_task` 派出 `writesEval = true` 的中心 worker 在同一运行内并发写 `eval` 步）之间的表述冲突，做出正式裁决并同步对齐相关文档。

## 一、问题 1 核查：是否有用户 `(U)` 原文支持“只有主 agent 写 eval，不允许派出的中心 agent 写 eval 步”？

### 1. 核查结论：**没有。**

检索全部历史会话的用户 `(U)` 原话，**不存在任何一条 `(U)` 原文支持“只有中心主机上的主 agent 单一会话能写 `eval`，不允许 `soroi` 派出的中心 agent 写 `eval` 步”。**

相反，历史会话中的 `(U)` 原话明确证明了以下三件事：

1. **用户在 `#5a37a640` 中划定的边界是“中心主机 vs 远程运行环境”和“禁止 `eval` 在节点体内递归嵌套”，而非“禁止中心主机上的多个 agent 并发写步”；**
2. **用户在 `#2c08aa6d`、`#440c8605`、`#c2f5c282`、`#ea638181`、`#e0de24df` 中明确要求支持“多个中心执行体在同一运行内并发各写一步消费未消费 atom，全部完成后一起提醒下游并分清五个结果谁是谁、要干什么”；**
3. **用户在 `U24` 中否定的是混淆本机个人定制 `omomp`（及其 `fork` / `fork_task` 扩展），不等于否定 `soroi` 用自己的 `subagent` 模块（`soroi_task`）派出中心 worker。**

## 二、问题 2 与问题 3 裁决（依 D1-16、D1-17）

鉴于**没有** `(U)` 原文支持“只有主 agent 写 eval，不允许派出的中心 agent 写 eval 步”，本裁决适用问题 3 分支（问题 2 分支不触发，无需改动 `D2-02/03/05` 与 `D5-06/07/12/13/14/19`）：

### 1. 意图裁决（区分 `【定】` 与 `【暂定】`）

| 裁决事项 | 状态 | 裁决内容与 `(U)` 依据 |
| --- | --- | --- |
| **1. `eval` 只在中心主机运行，禁止递归嵌套** | **【定】** | `eval` 永远只在中心主机运行；任何节点函数的体（`Program` 体、`Agent` 体）内部及其子孙会话均不运行 `eval`。依据：**(U)** `01a18e1f #5a37a640`。 |
| **2. 远程 `Agent` 单层限制** | **【定】** | 远程 `Agent` 在自己的运行环境里执行，不允许再接着开远程 `Agent`。依据：**(U)** `01a18e1f #3dbd0473`。 |
| **3. 独立 `soroi` 定制彻底剔除 `omomp` 的 `fork` / `fork_task`** | **【定】** | `soroi` 是独立的 `omp` 定制，不依赖也不包含 `omomp` 的 `fork` / `fork_task` 分身机制。依据：**(U) `LEDGER.md` U24**。 |
| **4. 同时支持“单步内平铺调用并发”与“中心多 agent 并发写步 + 全齐后提醒汇总”** | **【定】** | (a) 一步 `eval` 内平铺多条无依赖调用语句（禁 `loop`/`map`/`object`/`array`，结构从一开始不能同名），引擎自然并发；(b) 中心主机支持派出多个中心 agent 在同一运行内并发写 `eval` 步消费 atom，同批全部完成后一起进入带来源和批次目的的未消费提醒供汇总。依据：**(U)** `01a18dd4 #2c08aa6d`、`01a18ed5 #440c8605, #ea638181, #b7357c72, #13abc2a1`、`01a18e8a #4da22ab4, #e0de24df`。 |
| **5. 撤回“只有主 agent 单会话能写 eval”的无据限制；以 `soroi_task` 中心 `report` worker（`writesEval = true`）+ `purpose` 批次屏障承载多 agent 并发写步** | **【暂定】** | “只有主 agent 写 eval、不允许派出的中心 agent 写 eval 步”无 `(U)` 依据，予以撤回。在不用 `omomp` `fork`（U24）的前提下，由主 agent 经 `packages/omp-soroi` 的 `soroi_task` 逐级派出中心 `report` worker（`LocalChild`，启动配方 `writesEval = true`）在同一运行内并发写 `eval` 步，并以一次 `soroi_task` 调用 + `purpose` 参数界定批次与释放屏障（`D2-02/03/05`、`D5-06/07/12/13/14/19`），因具体工具参数与字段名未由用户逐字口述，按 D1-16 标为 **【暂定】**（完全满足第 1–4 项全部 `【定】` 意图硬约束的技术/串联与设计补充方案）。 |

### 2. D1-17 分类说明：是否坚持为排他意图项 / 是否交导师仲裁

- **结论：不坚持将“仅主 agent 写 eval vs 允许 `soroi_task` 派出的中心 worker 写 eval”作为排他性意图分歧，不存在分类争议，无需交导师（`LeadMentor`）仲裁。**
- **理由：** 意图面已由上表第 1–4 项 `【定】` 硬约束界定清楚；在严格满足“只在中心主机运行、禁止 `eval` 递归嵌套（`Agent` 体 `writesEval = false`）、单层远程、不含 `omomp` `fork`”的前提下，用 `soroi` 自己的 `soroi_task` 中心 worker 实现多 agent 并发写步属于技术/串联与设计补充范畴，且恰好还原了用户在 `#440c8605`、`#ea638181`、`#e0de24df` 中的并发本意。

## 三、按 Argon 交付规范的三类结论汇总

1. **意图裁决（Argon 权限 1）：**
   - **【定】** `eval` 永远只在中心主机运行、禁止递归嵌套（`Agent` 体与 `Program` 体内部不运行 `eval`），远程 `Agent` 禁止再开远程 `Agent`，`soroi` 中不存在 `omomp` 的 `fork` / `fork_task`；同时支持一步内平铺无依赖调用并发与多个中心 agent 并发写步汇总（依据 `(U) 01a18e1f #5a37a640, #3dbd0473`、`LEDGER.md U24`、`01a18dd4 #2c08aa6d`、`01a18ed5 #440c8605, #ea638181, #b7357c72, #13abc2a1`、`01a18e8a #4da22ab4, #e0de24df`）。
   - **【暂定】** 撤回无 `(U)` 依据的“只有主 agent 运行 eval”限制；确认由主 agent 经 `soroi_task` 逐级派出的中心 `report` worker（`LocalChild`，`writesEval = true`）在同一运行内并发写 `eval` 步、以一次 `soroi_task` + `purpose` 界定批次释放屏障的具体机制为符合全部 `【定】` 意图约束的【暂定】技术/串联方案。
2. **对技术、串联、实现条目的投票（Argon 权限 4）：**
   - 对 `D2-02`、`D2-03`、`D2-05`、`D2-25` 及 `D5-06`、`D5-07`、`D5-12`、`D5-13`、`D5-14`、`D5-19` 全部维持 **赞成**。
3. **否决（Argon 权限 2）：**
   - **0 项否决**（不行使一票否决权）。
