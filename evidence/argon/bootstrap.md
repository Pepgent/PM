## 一、我的权限与边界

我是 argon，Pepgent 项目中 soroi 及其周边组件的**用户原始设计意图守护者**。我的权限集中在四件事：**第一，本意裁决权**——任何设计、串联方案或实现取舍是否符合用户原意，以及当历史对话存在演进或局部张力时如何做意图层面的取舍，由我最终裁决；**第二，一票否决权**——针对缺失组件规划与设计补充，我拥有一票否决权，凡偏离用户本意或擅自收缩范围的条目，经我否决即不通过；**第三，逐条民主投票权**——作为领导小组（仅限 leader、leader 分身、task:high、argon、mentor）成员，我对决策表中的每个条目（含 what、where、how、取舍）投赞成或反对票并附理由；**第四，文档修正权与调查/实验调度权**——我负责直接补全和修正错误的设计文档（Markdown），并可随时派生 `task:mid`、`task:low`、`task:free` 收集证据或做实验（它们只交回证据，不参与设计判断）。我的边界同样严格：**绝不写任何代码**（不碰源码、测试、脚本、构建/部署配置及 omp 设置/agent 定义），**不越界包办纯技术/代码实现取舍**（技术取舍归 leader，遇混合问题先拆开，我只裁决意图那一半），**绝不向用户提问**，也**绝不把没有 `(U)` 依据的猜测或 assistant 超时自决包装成用户本意**。

## 二、新版 soroi 的意图要点（已由 `(U)` 证据确定）

### 1. 核心定位与控制面反转（Pivot 核心）

1. **AI 当函数运行的核心宗旨不变，普通程序与 agent 共处同一程序：**
   - 程序由纯程序与 agent 共同组成，agent 只是特殊的函数，目的是消除 agent 不可观测面、确定性捕获中间结果与运行时产物。

2. **彻底废除外部控制面、preset/workflow 弱编程语言与解释器 daemon：**
   - 旧设计假定 harness 弱且不可侵入，在外层造解释器+启动器 daemon 与 preset 定义流转；新版反过来以强 harness（omp）为核心，在 harness 内部直接给 AI 提供受约束的 `eval` 代码环境与自定义扩展包/工具完成调度与捕获，不再需要外层控制面或 preset 流转语言。
   - 依据：(U) `session://01a18dd4-e638-75ad-a5f3-f0537daf3896/entry/6b25e5f7`（02:30:39）、`#5ddb4d88`（02:31:00）、`#28767d47`（02:32:46）、`#2d861491`（02:33:44）、`#db50b20f`（02:44:01）。
3. **以 omp 为核心，严禁修改 omp 宿主代码，soroi 只做 omp 扩展组件（插件）：**

### 2. 值（atom）、节点函数与逐步 `eval`

5. **纯函数式不可变值（atom / `Pure<T>`）与消费推动的被动流程：**
   - 只有定量没有变量，底层是 `Pure<T>`，表层直接用 `const` 变量名表示 atom（不要求表层手写 `pure(...)` 包装）。
   - 每个中间结果都是不可变 atom，**必须被消费**；消费只有两种：**捕获**（作为参数传给节点函数并正式运行）或 **停止**（`stop`）。一个 atom 可被多处分支消费，每次消费派生新值，不加排他占有锁。
   - 依据：(U) `01a18dd4 #f1ad9522`（02:41:01）、`#afd96ce6`（02:48:47）、`#46e29915`（02:50:10）、`#d01f7a32`（02:51:49）；`01a18e8a #cab573e1`（06:33:37）。
6. **AI 不一次写完整流程，而是看未消费 atom 提醒一步一步写：**
   - `eval` 的核心价值是模型不必一次性写出完整流程脚本，每次只根据系统提醒的未消费 atom 写一步（消费一个或一组值），或 `fork` 分身并行消费；正式运行过的步在 store 里一步步长成完整程序。**从来没有“重放（replay）”整份脚本的机制。**
   - 依据：(U) `session://01a18ed5-5798-704f-aa9f-c28be4023631/entry/4986c617`（07:08:25）；`01a18dd4 #2c08aa6d`（02:56:20）；`session://01a18efe-a680-7642-aff1-6f468cf2935e/entry/9e2d37a1`（07:58:00）；`01a18e8a #21495b13`（08:47:13）。
7. **扁平 atom、运行内名字唯一、三语句限制与多输出对象解构（兼顾弱模型）：**
   - 语言只用 TS，不考虑 Python（`01a18dd4 #afd96ce6`）。
   - atom 扁平（标量或单个 `File`），不允许嵌套 object/array；一次运行内名字全局扁平唯一，不要步骤名或轮次坐标（`01a18ed5 #440c8605`、`#b7357c72`）。
   - 一步代码禁止 `loop`、`map`、定义 `object`/`array`，禁止魔法值字面量直接作调用参数（必须先绑具名根 atom）；TS 多返回值函数必须返回对象，并在调用处当场穷尽解构成独立命名的 atom（`01a18ed5 #13abc2a1`、`#276d1776`、`#98d47f20`；结合用户要求整体吸收 Gemini 讨论基线 `01a18e8a #e0de24df`）。
8. **节点函数是独立普通 TS 文件，体种类由构造器确定，捕获不依赖预声明输出或 Effect：**
   - 捕获看作 HKT，构造器确定是程序体（`Program`）、智能体体（`Agent`）还是人类接入（`Human`）；追踪和捕获不在 Effect 内部完成（`01a18dd4 #01b74874`、`#946fc403`、`#cb9f395b`）。
   - 节点函数写在独立普通 TS 文件里（不是 preset）；节点库不必删除，作为预定义持久化函数供后续 `eval` 导入传参复用（`01a18e8a #50f5cf06`、`#e7747df0`；`01a18e1f #47b71e05`）。
   - 运行前不靠 preset 预言输出；`Program` 由类 jotai 中间件捕获实际输入输出与非本机文件，`Agent` 通过调用宿主侧自定义交回工具（接收结果与文件路径）捕获运行时产物，中间件负责传输与管理（`01a18dd4 #edbaf573`、`#49e6867a`、`#ec8da5cc`）。
9. **两阶段运行（dry run 与正式运行）：**
   - `dry run` 本质是模拟测试（可在 Slurm 等环境真试跑算法，对昂贵设备或 agent 靠外部叠加返回值钉住而不侵入被测代码），**dry run 从头到尾绝不写 store**，跑成功与否直接看调用返回；`正式运行` 不带测试替身/模拟（业务写死的值就是普通根 atom），结果固化进 store，也不存在“锁定上一次 dry run”的机制。
   - 依据：(U) `01a18e8a #48078e3a`（06:45:30）、`#68d36f55`（06:47:05）、`#a7f465d2`（06:56:46）、`#8854f464`（08:52:18）、`#32b6f7fd`（08:54:56）、`#a45ac248`（08:56:18）；`01a18e1f #7ffcea0c`（08:30:15）。
10. **中心 `eval`、单层远程 `Agent`、禁止跨运行互见 atom：**
    - `eval` 永远只在中心主机运行，**禁止递归嵌套**；远程 `Agent` 爱怎么执行怎么执行，但**不允许再接着开远程 `Agent`**；atom 只在本运行内可见，严禁跨会话/跨运行直接互见和消费 atom。
    - 依据：(U) `01a18e1f #63f31453`（08:18:31）、`#9552d5c5`（08:21:03）、`#5a37a640`（08:25:02）、`#3dbd0473`（08:27:31）。

### 3. Store、远程落盘与 GUI 直读

11. **Store 是可落盘的状态管理（DuckLake + 对象存储），GUI 直接读 Store，不要额外 DSL：**
    - Store 不是 omp session log，而是落盘状态管理，直接解决值存储、捕获、按身份复用，前端连 DSL 都不需要；历史时间轴是极为重要的核心功能；数据不应先存无意义的二进制再在 DB 里重复抄一遍完整反向索引。
    - 偏爱 DuckDB 列式存储，认可 DuckLake：正式运行中的远程 `Agent` 在本机独立落盘，**只有运行结束后才随 volume 拷出一并汇入中心副本**，从而消除多集群并发写中央数据库的问题。
    - 依据：(U) `01a18e1f #64246eaf`（05:07:53）、`#9ff9d2be`（05:25:49）、`#d6cf9b35`（05:28:11）、`#543f0ccd`（05:29:58）、`#a5f938df`（05:31:07）、`#8e0a7e8f`（05:35:38）、`#3dbd0473`（08:27:31）。

### 4. 插件式 Subagent、独立网络层与 Remote

12. **以纯插件重写 omp subagent，独立 RPC 进程，生命周期与 IRC 全方位对标内置：**
    - 不改用无状态的 pi（因为 soroi 会唤醒早已死掉的 session）；不沿用必须走 `yield` 的内置进程内 subagent；以 **omp 纯插件** 重新实现 subagent，每个 subagent 是独立 `omp --mode rpc` 进程，对标主 agent 的定制，生命周期与 IRC 全方位对标内置 subagent，不考虑两侧版本一致问题，另需补齐部署与服务发现。
    - 依据：(U) `01a18e1f #9c291fe2`（04:12:48）、`#678fe41a`（04:39:09）、`#2dbf970b`（04:40:40）、`#7bfe3696`（04:42:56）、`#c1ef8567`（04:44:03）；`01a18f4a #f488be08`（09:12:17）。
13. **独立网络层与中心化 omp RPC 多路复用器（Mux）：**
    - 远程容器/机器如何连回 soroi，以及 GUI 如何只读观察任意 agent（RPC 只读多路复用），位于**独立的网络层**中，内含**中心化的 omp RPC 多路复用器**。
    - 依据：(U) `01a18e3a #09e1cc92`（04:53:33）；`01a18e1f #2dbf970b`（04:40:40）。
14. **独立跨平台程序 `remote`：三后端共享抽象（首期实现 Komodo），自动临时 volume 拷入拷出：**
    - `remote` 是独立跨平台程序（支持 Windows/macOS/Linux），兼顾三种后端：Komodo（对接 Docker）、Slurm（对接实验室集群，反对用 SSH，改走 HTTP/slurmrestd）、标准 K8s 控制面；三后端完全分离实现、**共享抽象和中间层（严禁删抽象）**，当前阶段先实现 Komodo。
    - 容器/Pod 模板预先构建，eval 调用只传简单模板名；文件走自动生成的临时 volume，运行时可覆盖挂载路径，结束后全自动把整个 volume 拷回调用方目标，容器与临时 volume 即可删除。
    - 依据：(U) `01a18e3a #c5030836`（04:15:49）、`#09e1cc92`（04:53:33）、`#5d27138c`、`#3afc3fb6`、`#c87758b6`、`#93b7f0b4`（05:05:53）、`#d5414f59`（05:10:07）、`#e5b56608`、`#2366ef30`（08:05:09）、`#56d362ca`（08:06:03）。

### 5. 人类介入（独立设计层）

15. **人类介入是独立的一层，只发生在正式运行上，只新增不合并改写：**
    - 人类介入是单独的一层（独立文档 `intervention.md`），同一规则不许在多个文档重复抄写。
    - 只有正式运行（固化）才能被人类介入：
      - **改值：** 不做多写方合并写入；等于取消正在运行的程序，原本要被程序消费的 atom 改由特殊的“人类接入（`Human`）”程序消费，产出新 atom，通知 AI 改变了并自动触发下游消费。
      - **改函数体或参数：** 人类修改正在运行的函数体或参数并派生新的闭包/运行，**永远是正式运行**（不覆盖旧运行记录）。
      - **人工接管 subagent：** 走既有 subagent 的 IRC 语义（可識別来源、可作为普通 user prompt 排队及被人类编辑）。
    - 依据：(U) `01a18e1f #7bfe3696`（04:42:56）、`#ba5ad307`（05:16:25）、`#d1baf561`（05:18:56）、`#a0d22b8a`（08:32:02）、`#2d06b34c`（08:33:32）、`#6145f170`（08:35:33）、`#f1f9c0b5`（08:36:30）。
