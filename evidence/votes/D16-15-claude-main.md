### D16-09 的反例

**场景：** D16-09 照录 G-1 表，W-06（store）、W-07（plugin）、W-08（e2e）的 `--cwd` 都是 `/Users/mouriya/Ext/code/pepgent/pepgent-soroi`。这个共享根 checkout 检出的是 `main`，主会话停在这里（C3-4.4），秘书提交 LEDGER 也在这里。三名工程师的 omp 进程从这里启动后，在建好自己的 worktree 之前做的任何写入、`git switch`、`git pull` 或 `bun install`，都会落在主会话的 `main` 工作副本上。

**证据：** D15-10② 的 soroi 盘点（`local://exec/d15/soroi.md` S080–S116、S119，以及第 344 行）记录了同一类失效。会话中的工程师在 07:18:52Z 于自己的 home worktree 执行了 `git switch --ignore-other-worktrees main`，让第二棵 worktree 也检出了 `main`。此后 `main` 继续前进，那棵 worktree 留下 37 个反向 staged 文件，其中包括删除用户授权的 argon-governance 和 watchdog。这些文件至今无法归因，只能永久冻结（D16-08②）。D16-09 现有文本没有禁止这种操作，而且把 `--cwd` 直接设在 `main` 所在的 checkout，失效面比原来更大。

**修改建议：** 在 D16-09 的 W-06、W-07、W-08 中各加一条：
1. 根 checkout 只作为进程的启动目录。工程师的第一步是执行 `git worktree add -b <切片分支> /Users/mouriya/Ext/worktrees/<会话名>-<issue号> origin/main`，之后所有读写和 git 操作都在这棵 worktree 内进行。
2. 禁止在根 checkout 中写文件、执行 `git switch`、`checkout`、`pull`、`commit`，或安装依赖。
3. 禁止使用 `--ignore-other-worktrees`，禁止让任何 worktree 检出 `main`。
4. 每个切片用一棵新 worktree，PR 合入后移除。

同一约束写入 D16-11 的派工消息白名单段。也可以采用另一种方案：在 tern 启动前，由主会话先为每席建好专属 worktree，再把 `--cwd` 设为该 worktree。两种方案都能消除这个反例，具体选哪种由起草方决定。
