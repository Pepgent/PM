# D18（PM#28）产品原始意图守护席 Argon 选票（v2）

表决对象为 `local://decisions/D18-product-opus-contracts.md` 第 19 行起的“发起人正式提案 v2”：D18-01 的 11 个子项、D18-02、D18-03 方案 C、D18-04 方案 A、D18-05 方案 C。

## 一、意图裁决

1. **D18-01 总边界【定】：业务面不得塞入 soroi 内核。** 依据 `(U) U1`：“soroi 本身相当于只是 omp 的扩展组件，离真正的 Pepgent 还很远”，且 Pepgent 下各组件像 remote 一样独立存在。具体由 Lab、remote、images、Komodo 或独立运维组件承载，是技术/串联取舍，不冒充用户原话。v2 的 11 项全部保持业务面在 soroi 内核之外，符合本意。
2. **D18-04【定】：智能体模板页只能编辑 omp agent 定义，其他 harness 不出线。** 依据 `(U) U13`：“核心的 ai harness，不能偏离以 omp 为核心，不修改 omp 的宿主代码”；`U24` 又明确 soroi 是独立 omp 定制。D18-04 方案 A 符合本意；恢复多 harness 的方案 B 与用户本意冲突，本席对方案 B 行使原始意图否决。
3. **D18-05【定】：Pepgent Web 是多 Lab 的唯一多租户层；soroi 不实现租户隔离，而是每 Lab 一套实例。** 依据 `(U) session 01a0d0f1-ef92-760c-b084-544d41a96888`：
   - entry `93d9c89c`：“实验室的抽象实际上是soroi多租户模式，而soroi多租户在早期直接用多实例解决”；
   - entry `bf96d256`：“你错了，web对接soroi多租户啊，我说的是多租户概念不侵入soroi，想什么啊”；
   - entry `4d388e7f`：“在新增实验室的时候，等于部署全套soroi下的东西成独立的一份，包括km，这样根本不存在手动做租户数据隔离”；
   - entry `d5277d47`：“而新增实验室等于部署，这个部分是个占位细节”。
   因此，Web 每 Lab 一份、在应用外切换的 v1 方案 A，以及多个 Lab 共用一套 store/Mux/remote 并在 soroi 组件内加 Lab 隔离的方案 B，都与原话冲突；本席分别行使原始意图否决。v2 方案 C 同时保留 Web 多 Lab 目录/切换和 soroi 每 Lab 多实例，准确落实原话；部署供给细节按用户指定保持占位。
4. **D18-02、D18-03 的具体措辞与终态形状属于技术/跨组件契约。** 未找到用户对这些字段和终态标签的逐字指定；本席只审查其不偏离 U1/U13/U23 的产品边界，不把技术选择标成用户本意。

### D18-02：设计正文与三仓目标、dry run、返回形状对齐

- **票：赞成。**
- **分类：同意“技术”。**
- **否决：否。**
- **理由：** 三仓目标和迁仓前互斥路径域是 D10/D16 已定边界；dry run 会使用并删除 transfer，但不写正式记录、中心副本与对象目录；“不预声明产出”只是不预声明捕获集和产物路径，不取消 TS 静态返回形状。执行附注已把关联文档位置纳入同一次直接替换，避免文档继续互相矛盾。该回写由 Argon 在条目通过后执行，不在投票前抢跑。

### D18-03：remote `Ended` 方案 C

- **票：赞成方案 C。**
- **分类：技术性跨组件公开契约。**
- **否决：否。**
- **理由：** `Ended` 统一表示作业已到执行终态；自然结束仍保证 copy-out 已送达。主动 `abort` 的调用已经由 eval 记为 `call_aborted`，发起方不读取其暂存区，因此允许 abort 后以 `Ended` 收尾但不承诺拷出，不会伪造可消费产出；远程 Agent 的有序停止走正常退出与 copy-out，复盘路径保持。方案 C 同时保留 remote 当前可完成的终态与 remove 主路径，不新增失败分支变体。

### D18-04：智能体模板页方案 A

- **票：赞成方案 A。**
- **分类：意图约束下的既定契约确认。**
- **否决：否（对方案 A）；方案 B 已在本票第一节依 U13/U24 否决。**
- **理由：** 页面编辑 Lab 库 `.omp/agents/` 中的 omp agent 定义；模型/provider 可以多种，但 harness 唯一为 omp。它与 D7-11、D12-intent 既有基线一致，不是恢复新的产品面。

### D18-05：多 Lab 隔离方案 C

- **票：赞成方案 C。**
- **分类：部署隔离原则为意图；按 `labId` 路由为技术串联。**
- **否决：否（对方案 C）；v1 方案 A 与共享 soroi 实例的方案 B 已依上述四条用户原话否决。**
- **理由：** 单一 Lab 后端/Better Auth organization 承载多个 Lab 的目录、成员、角色与切换；每个 Lab 路由到独立 store、Mux、Komodo、remote home、中心 omp 会话卷与 worktree 卷，soroi 组件本身没有 Lab 字段。该形状同时满足“Web 对接 soroi 多租户”“多租户概念不侵入 soroi”“新增 Lab 部署全套 soroi 下的东西包括 km”。部署单元供给方式按用户原话保留占位并假定可工作。
