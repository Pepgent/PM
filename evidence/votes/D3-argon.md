### 3. `【暂定】` 项裁决（依 U20 / D1-16）
`D3-network-mux.md:26` 引用的三项 `【暂定】`（出自 `argon/rulings-C.md:89,92,174`）及 `D3-12` 的队列撤回/编辑占位 `P4`（出自 `argon/rulings-C.md:286`）核定如下：
1. **【暂定 · 进程归属与二进制细节（`D3-02`、`D3-04`、`D3-07`、`D3-08`）】**
   - 用户原话 `(U)` `01a18e3a #09e1cc92` 明确规定了“在独立的网络层中，有中心化的omp rpc多路复用器”（此为 **【定】**），同时明示“怎么实现怎么干的你别管”。因此：将 Mux 实现为 Rust + tokio 单静态二进制、同二进制提供 `serve`（纯内存连接表与路由，不启动任何进程）与 `dial`（持有 omp stdio 出站拨入），且本机与远程进程统一由写方以 `dial` 启动（leader 裁决 D），不涉及违背 `(U)` 原话的冲突，维持 **【暂定】**，归技术/串联项由领导小组投票（Argon 投赞成）。
2. **【暂定 · 线协议帧格式（`D3-05`、`D3-06`）】**
   - WebSocket 逐行转发 omp RPC v1 JSONL、Mux 控制帧使用 `mux_` 前缀、读方命令 id 由 Mux 加 `r{conn}:` 前缀并广播 response，属于落实 `(U)` `01a18e3a #09e1cc92` 与 `01a18e1f #2dbf970b` 的具体协议设计，无逐字 `(U)` 规定帧格式，维持 **【暂定】**，归技术/串联项投票（Argon 投赞成）。
3. **【暂定 · 远程运行中本地 Parquet 批次经网络层可见的具体传输机制（`D3-13`）】**
   - **意图面【定】**：正在运行的远程 agent 本机独立落盘，运行结束后才随拷贝一起回集中副本，写回前不能被其他运行复用，而运行中进度经网络层只读可见（**(U)** `01a18e1f #8e0a7e8f`、`#bfd6975c`、`#63f31453`）。
   - **技术面【暂定】**：`D3-13` 通过 RPC 事件流触发 + 经同一条 `dial` WebSocket 连接转发 `mux_list_files` / `mux_read_file` 读取 `REMOTE_MOUNT` 下已原子改名的 Parquet 批次，完全满足 `design/store.md:70`（“从它的批次目录读取或经网络层订阅”）且保持容器纯出站连接，维持 **【暂定】**，归技术项投票（Argon 投赞成）。
4. **【暂定 · 已发出未投递 IRC 的撤回与编辑契约（`D3-12` 占位 `P4`）】**
   - **意图面【定】**：人工接管走 IRC，是普通 user prompt，“所以可以派对，乃至被人类编辑”（**(U)** `01a18e1f #7bfe3696`）。
   - **技术面【暂定】**：发送前草稿在 GUI 编辑，已入队未投递 IRC 的撤回与编辑（出自 `(A)` `01a18e1f #c7ab2296`）在 `D3-12` 中按设计阶段主路径规则列为占位 `P4`（先假定存在插件可调用的方式，不修改 omp 宿主代码），维持 **【暂定】**，归技术项投票（Argon 投赞成）。
