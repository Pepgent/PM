- 运行环境规定：用户的明确指令会覆盖它点名的规则与范围。U117 点名的正是仓 A、仓 B owner 的授权等待，也就是上位建仓规则“列出 owner 并等其选择”中“等其选择”这一环。所以这一步的例外是用户本人在 U117、U118 中作出的，不是借表决开的例外，AGENTS.md:125 禁止的情形不适用。

## 主路径失效反例
1. D53-01 通过：owner 为 Pepgent。
2. 按 D53-02 的 how，Main 在回复正文中列出五个 owner 后等待用户选择，两个仓不创建。
3. D53-03 第 1 步和 D53-04 第 1 步都要求“以快照建仓”导入新仓。新仓不存在，导入 PR 无处可开，A2-02、A2-03 停在开工前，D53-05、D53-06 又依赖这两项合入，于是整条迁仓链再次停在“等用户决定 owner”。这正是 U117 点名、U118 定性为“孤儿议题”的状态。D53-02 自己的取舍栏也写了“两仓的实际创建要等用户在回复中给出 owner”。
4. 以上可以复现：在本议程原样通过的情况下，执行到 D53-03 第 1 步时，`gh repo view Pepgent/soroi-store` 返回不存在，导入无法进行。

how 改为：D53-01 通过后，由 Main 以 RiriAgent 直接执行 `gh repo create Pepgent/soroi-store --private` 和 `gh repo create Pepgent/omp-soroi --private`。为了透明，在当轮回复正文中列出五个候选 owner 和本议程第 1 行的表决结果，但不等待选择。依据是 U117、U118 点名覆盖了该建仓事项上的等待。开仓以外的工作照原文立即进行。
