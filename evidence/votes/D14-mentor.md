## D14-01 分类终局裁决

**终局裁决：D14-01 属于“技术/补”，不属于“意图/修订”。**

理由如下：

1. **用户意图没有改变。**  
   用户已经要求按身份确定性复用、不重放，并要求远程与本机经过同一套中间件捕获。D14-01 没有改变“什么结果对用户算成功”、是否允许复用、是否允许重放，也没有加入新的产品策略。

2. **新增的是实现既有意图所必需的技术判等分量。**  
   旧公式遗漏了会改变 Program 执行和结果解释的发行代码，导致两个并不等价的执行可能被判成同一身份。加入发行身份是在修正技术上的假阳性复用，而不是重新定义用户希望何时复用。

3. **用户从未指定身份公式必须由哪些字段组成。**  
   节点版本、输入身份、环境身份、定制身份和现在的发行身份，都是系统为了实现“确定性复用”而选择的技术表示。增加其中一个必要分量，不等于增加一项用户意图。

4. **与已通过的 D4-18 分类同构。**  
   D4-18 把环境身份和 Agent 定制身份加入捕获身份时已经被归为“技术/补”。D14-01 同样是发现执行语义尚有一部分未被身份覆盖，然后把该技术分量补入公式；没有理由仅因它修订 D4-02 的公式就升级为意图项。

5. **扩大保守失效范围仍是技术粒度取舍。**  
   README 或仅影响 Agent 的文件变化也会让 Program 重算，属于选择整个 artifact 作为较粗身份单位所付出的性能成本。它不改变正确性目标；若实测成为瓶颈，再把发行拆成更细的确定性组件，仍是技术优化。

因此，我先前在缺少 D1-17 分类背景和完整 steady 证明时提出的“意图/修订”判断，由本次终局裁决明确替换为：

> **D14-01：技术/补。**
