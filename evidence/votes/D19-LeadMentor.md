# D19（原草稿编号 D18，SOR-13 控制端点线上契约）：LeadMentor 选票

GovClone 照录原票。原票按草稿编号 D18-01..05 投出，内容与 D19-01..05 逐行相同，以下只改编号，不改票面和理由。

|ID|票|理由|分类意见|
|---|---|---|---|
|D19-01|**赞成**|以 `method` 为判别字段把请求建模为封闭 sum type，使 mux 无须解释 body，而各端点可在自身边界穷尽解析合法 variant；根端点专属的 `writers / derive / abort` 与通用的 `slots / answer / takeover` 也得到明确区分，并同步消除 D12 序列图中的旧对象简写。|**串联，终局确认；属于补设计。** 它定义 Lab、根会话、会话端点与 mux 之间的跨组件请求契约，而非某个组件的内部实现。|
|D19-02|**赞成**|统一的成功／失败结果类型让所有调用方只处理一个判别入口；命令型方法以 `value:null` 表达已成功但无返回实体，查询型方法返回明确 value，避免用 HTTP 成功、空 body 或异常字符串猜测业务结果。|**串联，终局确认；属于补设计。** 它统一多个端点和调用方之间的回复契约；`slots` 的 `[{slot,fn,state}]` 是该跨组件契约的一部分。|
|D19-03|**赞成**|返回 `{session,endpoint}` 的结构化记录并包含根会话，使 session 身份与可调用端点的映射由服务端明确给出，消除了“各自端点名”与裸 `string[]` 之间的歧义，也无需客户端自行拼接或推断遗漏根会话。|**串联，终局确认。** 这是根会话向调用方交付 writer 会话及其端点寻址信息的契约。|
|D19-04|**赞成**|线上继续使用既有 `{kind:"record",fields}`，保持 D5、D12 的公开 Shape 权威；插件内部 `{kind:"fields"}` 只作为内部表示，并在端点出口完成一次确定性转换，避免内部模型泄漏后形成第二套线上契约。|**技术，终局确认。** 这是边界序列化 Shape 与插件内部表示之间的技术转换规则。|
|D19-05|**赞成**|`run:null` 查询的是指定 `eval:<根会话>` 所拥有的“尚未建立运行的在途步”，并不伪造 RunId，也不提前移动 D6-05 的运行开始锚点；Lab 先从 D7-04 的 conversation 权威记录取得根会话 id，再向该端点发现首步 Human 槽位，运行建立后切回 RunId 寻址，补齐了首步等待交回的真实主路径。`answer / takeover` 仍由会话端点结合 slot 定位目标。|**串联，终局确认；属于补设计。** 它衔接 conversation、会话端点、Human handback 与 store 运行生命周期，解决的是跨组件开始锚点之前的发现路径。|

**结论：D19-01 至 D19-05 全部赞成。**
