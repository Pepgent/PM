## 一、本轮涉及的意图行与核心追加修订裁决（`D2-04`、`D2-12`、`D2-25`）

### 1. `D2-04`（store 服务，分类：意图）—— **【定（HTTP 接口与来源证据细目为暂定） · 赞成】**
- **最新文本核对与意图裁决：**
  1. **【定 · 归属与伴随进程边界】** store 属于 soroi，归 `Pepgent/soroi` 单仓 `packages/store` 同版本发布；单写方只增不改伴随进程不违背 U1/U13/C-1（**(U)** `01a18dd4 #2d861491, #6b25e5f7`、`01a18e1f #64246eaf, #8e0a7e8f`、**LEDGER U1, U13, U23**）。
  2. **【定 · 无 FTS 派生表、时间轴与暂存区】** 直接对 DuckLake 文本列做 SQL 匹配、不建重复 FTS 派生索引（**(U)** `01a18e1f #543f0ccd`），保留事件表历史时间轴（**(U)** `01a18e1f #9ff9d2be`），远程 `dry run` 只经暂存区不进中心副本（**(U)** `01a18e1f #7ffcea0c`、`01a18e8a #32b6f7fd`）。
  3. **【定 · 保存节点版本首次正式提交的 bundle 及不可变来源证据】** 节点版本首次正式提交时，store 除保存 bundle 外同时保存不可变的来源证据（入口 TS、源码清单与 source map、Git commit、构建 manifest 与 lockfile 身份，D6-21）作为历史执行证据，既满足 **(U)** `01a18e8a #50f5cf06, #e7747df0, #8d913d2f, #f4c96767`（节点是普通 TS 文件、处理依赖与 `package.json`）与历史回看需求（**(U)** `01a18e1f #9ff9d2be, #e3692177`），又不侵犯 Git 默认分支作为“当前定义”的唯一权威。

### 2. `D2-12`（节点库与 agent 定义，分类：技术）—— **【赞成】**
- **最新文本核对：** 明确 Git 默认分支是“当前定义”的唯一权威，每个根会话用独立 git worktree 作 `cwd` 供 AI 编写/修改节点并直接 `dry run` 试跑、合入默认分支才算持久化；节点版本首次正式提交时在 store 保存 bundle 与不可变来源证据（入口 TS、源码清单与 source map、Git commit、构建 manifest 与 lockfile 身份，D6-21）供历史回看。完全符合 **(U)** `01a18e1f #47b71e05`、`01a18e8a #50f5cf06, #e7747df0, #8d913d2f, #f4c96767` 及 `argon/version-ruling.md`。

### 3. `D2-25`（soroi omp 定制，分类：意图）—— **【定 · 赞成】**
- **最新文本核对与意图裁决：**
  1. **【定 · 安装 manifest/installer 与干净上游 omp 前置验收】** release artifact 内带安装 manifest 和 installer，只用 omp 公开机制将 extension、agent、skill、rule、settings 装到 omp 支持的位置，中心（D2-20）与远程（D2-11）走同一安装过程；并在第一段验收前增加前置验收：“在不含 omomp、HOME 为空的干净上游 omp 中安装 artifact 后，实际枚举并执行 extension、agent、skill、rule、settings 每一类内容，证明全部生效”。直接落实 **(U) LEDGER U13**（不修改 omp 宿主代码）、**(U) LEDGER U23**（完整的 omp 定制）与 **(U) LEDGER U24**（彻底排除 omomp、`fork` 及本机 HOME 配置的隐式依赖）。
  2. **【定 · 两段式验收与点线面差距盘点】** 第一段用测试客户端扮演 Pepgent，只经 Mux 与 store 走通 soroi 一侧全部流程；第二段接上 Pepgent 走通 GUI 与 Lab 业务，两段之差即 U23 要盘点的“点、线、面”，完全契合 **(U) LEDGER U23**。
