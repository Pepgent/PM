# D13 导师两轮选票原文

最终有效票：D13-01、D13-03、D13-05 沿用第一轮赞成；D13-02、D13-04 第二轮改投赞成。五项均赞成。

## 第1轮原文

## 导师族投票

结论：**3 票赞成，2 票反对**。反对的是 **D13-02** 与 **D13-04**；两项都有会在主路径上发生、且能直接证明契约失效的具体反例。

| ID | 票 | 理由（反对附具体反例） | 分类意见 |
|---|---|---|---|
| **D13-01** | **赞成** | 权威边界和生命周期划分正确：部署是中心镜像与运行配置身份的生产方，插件只在 Main 启动时解析一次并消费，不在容器内反推部署状态；LocalChild/RemoteChild 不要求这些值，也避免把 Main 生命周期的配置误加到子角色。`sha256:<64位小写hex>` 与 remote 的身份编码一致，同时使用独立 digest 类型，避免与 store 的无前缀键混淆。字面量 `central` 仅保留为显示值而不再承担身份语义，也是干净切换。现有 env 传播链是否确实覆盖根 omp 是实现期必须验证的事实，但不影响该接口设计本身。 | **串联/补，分类正确。** 它没有改写 D4-18 的意图，而是在部署生产方、根 omp 和插件消费方之间补齐变量名、编码、角色范围及传递接口。不是新的意图决策。 |
| **D13-02** | **反对** | **反例一——同一运行配置可以被两个合规生产方算出不同 digest。场景：** deploy 的 Python 生产方把路径编码成 `"/opt/omp/config.yml"`，standalone/e2e 的另一个 JSON 序列化器把同一路径编码成 `"\/opt\/omp\/config.yml"`；两者都是合法 JSON，都满足“无空白、非 ASCII 原样”，但 UTF-8 字节不同，最终 SHA-256 不同。**证据：** 本条明确存在 deploy 与 standalone/e2e 两个生产方，却只规定“JSON 无空白、非 ASCII 原样”，没有规定 ASCII 字符的唯一转义规则；尤其 `/` 是否转义没有被约束。`files` 中“文件字节 sha256”也没有规定内部值究竟是 64 位 hex、`sha256:<hex>`，还是其他表示。**失效位置：** “两生产方规则相同可审计”以及“中心配置身份有唯一编码”失效；它没有真正补完 D4-18 原先缺失的“编码”契约。最小修正不是在实现中碰巧让两端使用同一库，而是把待哈希的规范字节流完整定义出来，包括字符串转义和内层文件摘要的精确表示。另有一项待核实事实：当前容器声明中是否还有会改变执行的 `working_dir`、`user`、额外挂载或同类配置；在该事实确认前，不能证明 `entrypoint/command/files` 就是完整投影。 | **不应只标为“串联/补”。** “谁产生”属于串联，但“以哪些字段、怎样规范化、怎样形成 digest”是核心技术契约；更准确是 **技术/补（兼串联）**。它不是意图项，因为“部署生产、插件消费”的意图已经由 D4-18 确定。 |
| **D13-03** | **赞成** | 一次性同时接入中心与远程身份，避免出现一段时期内只有一侧身份进入公式的中间状态；`kind/image/config` 作为确定性结构进入捕获公式、store 仅把结果当不透明键，也保持了职责边界。旧捕获不迁移、不再复用，与捕获公式发生语义变化相符。此票赞成的是“一次切换”的实施策略；**D13-02 的编码契约必须先修正，D13-03 才能据此实施**，但这不否定本条自身的切换策略。 | **实现/否，分类正确。** 它决定落地顺序、切换原子性和旧数据处理，不增加新的产品意图，也不应被拆成两次部分切换。 |
| **D13-04** | **反对** | **反例——升级前已经停驻的会话在升级后仍无法按 D7-07 读取。场景：** 某 conversation 在本变更部署前已经停驻；迁移只新增可空列且不回填；部署后该会话没有再开一代。用户此时读取 transcript。**证据：** 本条自己明确写明“迁移只加列不回填”以及“本变更前停驻且未再开代的会话没有引用”；同时又禁止唤醒、扫描和推断路径。**失效位置：** 该行的 `session_file` 为 `NULL`，在线 Mux 不存在，又没有任何被允许的路径可以取得 transcript，因而直接违反 D7-07 的“停驻时读 `get_state.sessionFile` 指向的 jsonl，不唤醒”。这不是异常输入或竞态，而是数据库迁移后的正常存量主路径。除非有明确事实证明部署时没有任何需要保留的 conversation，或用户明确批准丢弃这批会话的 transcript 能力，否则该取舍不能自行覆盖已通过的 D7-07。对于新会话和此后每一代，保存源头返回的 `sessionFile`、停驻后把它当外部引用读取的方案本身是正确的。 | **串联/补，分类基本正确。** 它把 omp 的权威路径、Lab 持久记录和在线/停驻读取路径串联起来，并补齐 D7-07 的持久引用；数据库列与解析必填属于实现细节。反对点是迁移范围没有覆盖既有契约，不是分类错误。 |
| **D13-05** | **赞成** | 中心 runner 不再继承整个中心进程环境，直接消除了身份公式之外的隐式执行输入；固定 `PATH` 与 `BUN_BE_BUN=1` 后，这些值由插件实现确定，PATH 下工具内容则由镜像 digest 覆盖。节点外部值通过 atom 参数显式传入，需要凭据的 Program 放到 remote 模板并由部署注入，符合 D4-10 的边界，也避免把中心容器中的 `BETTER_AUTH_SECRET`、`MUX_AUTH_TOKEN`、gateway token 意外传播给节点。明确 LocalChild 启动的 Agent 进程不受影响，范围也足够清楚。 | **技术/补，分类正确。** 它是在既有身份意图下收紧 runner 的执行输入面，使 D13-02 的窄投影有成立条件；不是新增产品意图。 |

## 缺少、但会影响最终裁决或实施验收的事实

1. **D13-04 的存量事实：** 部署时是否存在必须保留的既有 conversation，尤其是已经停驻且不会再开代的会话；以及是否已经获得用户对清空数据库或放弃这些 transcript 的明确授权。  
   - 如果确认没有存量，或明确批准丢弃，D13-04 的反例不再落到实际迁移对象上，我对该条可以转为赞成。
   - 在没有这一事实或授权时，“不回填”不能默认覆盖 D7-07。

2. **D13-02 的配置投影事实：** deploy 与 standalone 的真实容器声明中，除 `entrypoint`、`command` 和列出的文件外，是否还有会影响中心执行语义的 `working_dir`、运行用户、额外挂载、平台选择或其他运行参数。  
   - 这决定当前字段集合是否完整。
   - 但即使确认没有其他字段，JSON 字节编码和内层文件摘要表示不唯一的问题仍然存在，因此不会单独使当前 D13-02 通过。

3. **D13-01 的实现验收事实：** 两个新变量是否确实经过部署变量、中心容器、入口脚本及现有 env 传播链到达根 omp；插件是否只在 Main 路径解析。该事实应通过实际部署入口验证，但它不是本条设计投票的缺口。

4. **D13-05 的实现验收事实：** 所称 13 个现有库节点确实没有读取 `HOME` 或其他继承 env，并且真实 Program 入口在固定 PATH 下运行成功。背景已经把“无 env 依赖”作为事实给出，因此我不据此反对；落地后仍须走真实节点执行路径验证，而不能只看类型检查或静态搜索。

## 对“登记但未列条目”的意见

“**Program 捕获身份不含 runner，runner 改变后仍可能复用旧捕获**”是一个真实的身份失效缺口，应当保留登记，并由 leader **另开一项对 D4-02/D4-18 的正式修订决策**，而不是暗中塞入 D13-02、D13-03 或只在实现中加字段。

处理原则：

1. **必须中心与远程对称修订。**  
   不能只给中心捕获加入 runner 身份；否则会破坏 D4-04 的同一路径原则，并留下远程侧相同的错误复用。

2. **先确定 runner 身份的权威源头。**  
   需要明确“runner”究竟由哪个已存在的构件/version 代表，还是需要新增一个由 runner 构建或部署方产生的身份。不能从附近已有的镜像、bundle 或配置记录猜一个值冒充 runner 状态。

3. **它不是当前 SOR-07 一次切换的阻塞项。**  
   D13-03 会让切换前捕获整体不再复用，因此 D13-05 本次 runner 可见环境变化不会继续命中切换前的旧捕获。没有必要为了这个独立修订，把 SOR-07 的身份接入继续扩大。

4. **但它必须在下一次 runner 行为或版本变化前解决。**  
   D13 切换完成后产生的新捕获，如果此后 runner 再升级而身份公式仍不含 runner，就会重新出现错误复用。因此它可以不阻塞当前切片，却不能被当作普通备忘长期搁置，更不能在未修订时宣称捕获身份已经完整。

5. **分类应是“意图/修订”，随后再派生技术与实现项。**  
   它修改的是“什么变化必须使捕获失效”这一已通过契约，而不只是编码方式或接线方式。leader 先决定是否及如何修订 D4-02/D4-18，再确定具体身份表示与切换实现。
