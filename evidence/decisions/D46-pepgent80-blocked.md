**F1（成员族）。** D12:216（D43-01 v1 回写）：“成员与结论确认两族命令成功落库时，在同一事务写一行 activity。” D7-03：organization/member/invitation 是成员、角色、邀请的唯一权威。Better Auth 1.7.14 的 `createInvitation`、`updateMemberRole`、`removeMember` 在端点内逐条 `await` adapter 写库，写库之后才调 `after*` 钩子，三者都不包整体事务（`organization/routes/crud-invites.mjs:224,239`，`crud-members.mjs:218,224,361,363`）；Lab 的 `drizzleAdapter` 没有开 transaction（`server/lab/auth.ts:19`）；better-sqlite3 的事务回调返回 Promise 时直接抛错（`lib/methods/transaction.js:67`）。`member.quota` 写 Lab 自有的 `member_profile`，可以同一事务。

**F2（containers / P15）。** P15：“Lab 能从 images 检出读出每个镜像的 `ImageDefinition`……假定能工作”（D12:659）。`ImageDefinition{name, path, base, dependencies{name, version, kind(六类)}, files{path, size, contents}}`（D12:369-373）里，`path`、`base`、`kind`、`files` 都没有定义语义。Lab 运行时没有 images 检出配置（`server/lab/runtime.ts:23-60`）。deploy 已挂载 `images-checkout:/var/lib/pepgent/images`，但没有对应的环境变量；卷表写明写方是“Lab 后端”，生命周期是“images 仓库的独立可重建检出”（deploy `compose.yaml:113`、`README.md:135`）。同类路径接口的先例是 D21-01、D22-01。`Pepgent/images` 是私有仓库，只有一个根 `Dockerfile`（11 个 stage）和 README；README 说明发布目标只有 `omp-agent`、`central`、`lab-web` 三个，仓库里没有机器可读的逐镜像清单。

**F3（settings 成员状态）。** `MemberStatusWire{lastActiveAt: Instant | null; online: boolean}`（D12:374）。这两个字段都不在“第一版无来源字段”表里（D12:630-649），D7 settings 行的来源只写“Better Auth 成员/角色/邀请/授权”（D7:106）。Better Auth 的 session `updatedAt` 只在超过 `updateAge`（默认 86400 秒）后才刷新（`create-context.mjs:147`）。Lab 的 `GET /api/lab/events` 在 `server/lab/http.ts:57-64` 判定成员身份后订阅 `LabEvents`。

**F4（agent 模板）。** D7-11：“智能体模板是 `.omp/agents/` 的 omp 定义：id=定义名、harness='omp'、版本取容器 omp；文件和 models 取源码/frontmatter……saveVersion{conversation,id} 等于 library.merge 对应 `.omp/agents/<id>`”（D7:71）。`AgentTemplateWire{id, description, models: string[], files{path, contents}[], lastCommit, drafts}`（D12:267-272）。Lab 库现有三个定义都是 `.omp/agents/` 顶层的单个 `.md` 文件，文件名主干等于 frontmatter `name`，都没有 `model` 字段（lab-library `.omp/agents/*.md`）。omp 按单个 `*.md` 加载定义，不递归，定义名取 frontmatter `name`，`model` 可以是字符串、逗号串或 YAML 列表（W-09 引 omp 源码，(A)）。`apps/web` 没有 YAML 解析依赖。D16-09 的 W-09 行原本包含 `apps/web` 的 package manifest 与 lockfile，但 D42-01 v1 把 LAB-13 限定在 `server/lab/**`。
