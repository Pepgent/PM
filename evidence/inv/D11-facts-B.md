### LR-47：新增 wire 不止 global cursor 算法

(D) D6:34、217 已定 `after=<global cursor>` 且 cursor 是 string；D6:37、210–216 已定先 graph 再续订与 RunEvent 形状。LR-47 的两个公开评论分别增加：

1. **持久化及旧库首次发布语义**：(A) [6553683064](https://github.com/Pepgent/soroi/issues/190#issuecomment-6553683064) 的 nullable `events.lifecycle_cursor`、仅三个 lifecycle event 同事务 MAX+1；旧事实按 at/run_id/seq 一次性分配，明确不声称恢复真实历史全局提交顺序。MAX+1 可是实现选型，但迁移排序的外部游标语义不是私有。
2. **run SSE resume/结束**：(A) [6553868611](https://github.com/Pepgent/soroi/issues/190#issuecomment-6553868611) 规定 after 非负 safe integer、默认0、严格 greater-than，SSE id=十进制seq/event=kind/data=RunEvent；unknown run 在 headers 前404，非法 after400；terminal 历史发完 EOF。
3. **lifecycle resume/结束**：string十进制、非负 signed-BIGINT 范围、默认"0"、严格 greater-than；derivedFrom 仅父 run id/null（这点与 D6:217 一致）；持续到 client cancel/服务关闭。
4. **记录物化**：call events 增 incoming `edges`；step_committed 与 run_started 增 `records:{nodes,edges}`，尤其派生 run seq1 已物化继承状态；后续 call events 不代表节点此时才首次可见。consumer 必须按 root.name、call(step,position)、edge目标三元组 upsert。这些字段不在 D6:210–215 的 literal ADT 中。
5. **IO 实现**：DB exclusive 只物化，不跨网络持连接；唤醒只表示重读 durable source；COMMIT后通知、rollback不发；停止 accept→中止SSE→drain→DB close；无 payload cache/heartbeat/retry。这些内部调度细节不应全部升级成公开投票项，只有消费者可见的 close/EOF/record 语义是本报告的契约建议。
